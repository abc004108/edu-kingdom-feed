How it works
The enabled schedule runs once every FOUR HOURS, around 00:17, 04:17, 08:17,
12:17, 16:17, and 20:17 Hong Kong time. One RSSHub container and browser helper
are started per run, and one browser session is reused across all forums.
It publishes one validated RSS file per forum through GitHub Pages.
Your PC can be off. This hosts a periodically updated feed, not a continuously
running public RSSHub API. Only the public feed and code are uploaded.
No personal credentials, copied forum cookies, or private computer files are
required. Temporary helper/browser sessions are destroyed after each run.

Free requirements
Use a PUBLIC repository on GitHub Free and standard ubuntu-latest runners.
GitHub documents free standard runner usage for public repositories and free
Pages hosting for public repositories. This workflow uses a cached image,
short-lived small Pages artifacts, no paid runner, and no paid host or registry.
Repository and feed will be public. GitHub's plan limits and policies apply.

Deployment
1. Create a public GitHub repository named edu-kingdom-feed with main as its
   default branch. Upload this folder's CONTENTS, including .github, to its root.
   Do not upload this chat's other files, the installer, or Docker logs.
2. In repository Settings > Pages, select GitHub Actions as the build source.
3. In Actions, run "Update Edu-Kingdom feed" manually to test it.
4. Check the job's success and published feed before subscribing.
   Your feed URL will follow this pattern:
   https://YOUR_GITHUB_USERNAME.github.io/edu-kingdom-feed/feed.xml
   This is a template, not an existing deployed URL.

Operation
The first job builds RSSHub plus Chromium and caches the image. Later runs
restore that image, start a temporary container, fetch the forum, and stop it.
A build may take 15 minutes or more. Source is pinned to the locally tested
RSSHub revision. Updating that revision requires changing both the ref and
cache key in the workflow and checking compatibility with the route.
If a forum fetch fails, its last validated published feed is kept while other
forums update. status.json records which feeds were updated or preserved.
If a newly added forum has never had a valid feed, the existing site is kept
until all configured forums have a valid fresh or saved feed.

Add or remove subscriptions by editing forums.json. Each entry needs an id and
name. The current IDs are 368, 7, 709, 715, and 6. Each publishes at feeds/ID.xml.
The original feed.xml remains an alias for 368, preserving existing subscriptions
and item GUIDs. Import subscriptions.opml to subscribe to all configured forums.
Configuration changes do not rebuild the cached RSSHub image.

Limits
The forum's security checks may change. Current GitHub-hosted collection has
passed; future successful access is not guaranteed.
Schedules can be delayed or dropped. Public-repository schedules are disabled
after 60 days without repository activity and may require re-enabling.
Only the latest page of topics is fetched; long outages may miss topics.
The first successful run publishes the existing latest batch as well.
Use a reader that deduplicates stable GUIDs and mark that initial batch read.
